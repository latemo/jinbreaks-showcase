# jinBreaks | AI 업무 실행 플랫폼

**작업 요청부터 승인·실행·결과 기록까지 연결하며, 불확실한 실행을 성공으로 덮어쓰지 않는 흐름을 구현합니다.**

React · TypeScript · Vite · Hermes Runner · Obsidian · Slack · Telegram

[실제 화면·설계 사례·검증 기록](https://orivon-systems.vercel.app/project.html?id=jinbreaks)

## 직접 구현한 범위

- 작업·에이전트·스킬·위키 관리 웹 인터페이스
- 실행 승인·재시도·취소·결과 기록
- 로컬 Runner와 기록·메시징 서비스 연동 경로
- 실행 ID와 차수 비교를 통한 중복 종료·오래된 응답 처리

## 처리 흐름

사용자 요청 → 승인 → 작업 큐 → 로컬 Runner → 실행 결과·영속 기록

응답 유실 → 불확실 상태 보존 → 실행 확인 → 검토 후 종료

## 핵심 설계 판단

### 응답이 없다는 이유로 재실행하지 않기

실제 작업이 이미 실행됐는데 응답만 유실됐을 수 있습니다. 즉시 재시도는 부작용을 중복 발생시킬 수 있어, 불확실한 상태와 확인 경로를 별도로 둡니다. 자동 복구 속도보다 기록의 일관성과 중복 실행 위험 통제를 우선한 선택입니다.

### 과거 결과가 현재 실행을 덮어쓰지 않게 하기

실행 ID·차수와 현재 상태를 함께 비교합니다. 이미 확정된 기록에 대한 중복 종료 및 뒤늦은 결과는 같은 변경으로 받아들이지 않습니다. 운영 환경의 경쟁 상태에는 DB 원자성·락 등 추가 보장이 필요하며, 아래 메모리 예제만으로 이를 보장하지 않습니다.

## 검증 기록과 시연 경계

공개 포트폴리오의 **2026-09-30** 기록에는 실행 결과 정리 경로의 단위 테스트 5개 통과가 명시되어 있습니다. 메모리 저장소를 사용하는 검사이며, 외부 서비스 실행이나 모든 Runner 작업의 통합 검증은 아닙니다. 이번 업데이트에서 비공개 운영 테스트를 재실행한 것은 아닙니다.

기존 공개 스크린샷은 당시 클라우드 요청 한도로 실행 준비 확인이 실패한 상태입니다. 완료된 실행 화면으로 소개하지 않습니다. 실제 서비스는 로그인·로컬 Runner 설정이 필요합니다.

## 로그인·API 없이 확인하는 예제

[runner-example.js](runner-example.js)는 실행 차수 확인, 검토 후 종료, 중복·오래된 요청 거부를 설명하는 순수 함수 예제입니다. 실제 Runner를 실행하지 않습니다.

```sh
node runner-example.js
```

별도 패키지 설치가 필요 없습니다. 2026-10-19 JavaScript 실행 환경에서 독립 검사 8개 통과를 확인했습니다. Node CLI 별도 실행·원자적 DB 변경·작업 큐·외부 도구 실행을 검증한 결과가 아닙니다.
